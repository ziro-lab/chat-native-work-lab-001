# Audio loop recovery benchmark 001

## Goal

Prove that this public lab can generate a deterministic, redistribution-safe benchmark for **musical loop-candidate recovery** without relying on byte-identical repeated audio.

The experiment starts from a known eight-bar loop structure, renders multiple musically equivalent but sample-different takes, then emits ranked-candidate queries containing:

- one known positive transition: end of bar 8 -> start of bar 1;
- several **hard negatives** that are still aligned to downbeats but point to the wrong phrase position;
- an off-beat negative;
- machine-readable Ground Truth and scoring metrics.

This is intentionally the benchmark foundation, not the final YMM4 loop detector.

## Why this shape

A trivial benchmark made by copying the same PCM loop several times can be solved by exact waveform matching. That would overstate real-world loop-analysis quality.

This experiment therefore keeps the musical plan fixed while changing each take's gain, oscillator phase, timbre and deterministic noise. Corresponding takes are required to have different PCM hashes.

```text
known 8-bar musical loop
        |
        +--> take 1 (variation A)
        +--> take 2 (variation B)
        +--> take 3 (variation C)
                  |
                  v
       Ground Truth candidates
                  |
          detector predictions
                  |
                  v
      Hit@1 / Hit@3 / MRR /
      pairwise ranking accuracy
```

## Current fixture

- sample rate: 16 kHz mono
- tempo: 120 BPM
- meter: 4/4
- loop length: 8 bars
- takes: 3
- positive per query: 1
- hard negatives per query: 5
- source material: fully synthetic, generated by repository code
- deterministic seed: `20260917`

Generated WAV files are **workflow artifacts**, not committed source assets.

## Metrics

`evaluate.py` consumes a prediction file that assigns a score to every candidate for every query.

The report contains:

- `hit_at_1`: positive is ranked first;
- `hit_at_3`: positive appears in the top three;
- `mrr`: mean reciprocal rank of the positive;
- `pairwise_ranking_accuracy`: fraction of positive-vs-negative pairs where the positive receives a higher score (ties count as 0.5).

The pairwise metric is useful while tuning a loop-quality score because it directly answers whether known-good transitions outrank known-bad alternatives.

## Reproduce locally

Requires Python 3.11+ and uses only the standard library.

```bash
python verify.py
```

Outputs are written to `out/`:

- `take-1.wav` ... `take-3.wav`
- `manifest.json`
- `predictions-oracle.json`
- `predictions-random.json`
- `report-oracle.json`
- `report-random.json`
- `evidence.json`

## Assertions / PASS boundary

`verify.py` requires all of the following:

1. three deterministic takes are generated;
2. their PCM hashes are all different;
3. every query contains exactly one positive and at least five hard negatives;
4. the oracle scorer achieves 1.0 for Hit@1, Hit@3, MRR and pairwise ranking accuracy;
5. the deterministic random baseline ranks worse than the oracle;
6. the run writes `status=PASS_AUDIO_LOOP_RECOVERY_FIXTURE_V1` in evidence.

PASS proves that the lab can produce and score a non-byte-identical Ground-Truth loop-recovery fixture.

## NOT PROVEN

This experiment does **not** prove:

- that a real music-analysis algorithm can recover the positive transition;
- perceptual naturalness on ordinary commercial music;
- Beat / Downbeat accuracy;
- harmonic or structural segmentation accuracy;
- sample-accurate seam quality after a jump;
- click/pop suppression or optimal crossfade rendering;
- YMM4 plugin integration.

Those should remain separate experiments so one green benchmark does not silently become a product-quality claim.

## Next experiments

The intended sequence is:

1. add a lightweight public-tech baseline (Beat/Downbeat + DSP similarity);
2. compare known positives against hard negatives with the same evaluator;
3. add structure-preserving codec/EQ/reverb/stem-balance transformations;
4. add public, license-vetted real loop sources without committing restricted audio;
5. only then compare heavier structure-analysis models;
6. move the winning analysis path into the YMM4-side prototype.
